# 问题与实验记录

## 2026-11-04：基线建立

| 现象 | 原因与处理 | 可解释的边界 |
|---|---|---|
| 旧任务路径与中文50题入口不同 | 固定v2.0.0并核对发布的text-v1语言/领域单元，使用规范ID映射到中文任务 | 只报告中文零售单元 |
| 本地Python3.14不满足上游要求 | 上游要求>=3.12,<3.14；远程使用Python3.12与独立环境 | 本地标准库测试不等于上游完整运行 |
| 新模型强度可能被旧LiteLLM静默过滤 | 上游设置drop_params=True；使用extra_body直接透传请求字段并做工具往返探测 | HTTP成功仍需服务端证据证明实际执行强度 |
| 当前只有Codex登录，没有独立API凭据 | 使用显式Codex桥接配置；保留原生Agent、工具和评分规则 | 传输及模型配置与官方直连条件不同，必须单独标注 |
| NL断言裁判模型在代码常量中固定 | 用受控启动钩子在父/子进程启动时替换配置及裁判模块中模型常量，语义通信裁判通过CLI传参 | 只改变裁判模型条件，不修改评分规则或答案 |
| 未识别模型价格被上游记为零 | 本项目报告实际费用为null，保留观察到的token和账单待核验说明 | 不把未知费用当免费 |
| 只统计成功返回轨迹会高估成绩 | 以运行清单题数×试次数固定分母，缺失和异常仍计入 | 未完成实验不能参与最终档位选择 |
| 相同用户/订单多道任务可能跨组 | 用实体与模板关联传递分组，冻结25/13/12清单 | 还需人工核查语义近似模板，不宣称独立泛化 |
