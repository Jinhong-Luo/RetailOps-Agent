# 问题与实验记录

## 2026-11-04：基线建立

| 现象 | 原因与处理 | 可解释的边界 |
|---|---|---|
| 旧任务路径与中文50题入口不同 | 固定v2.0.0并核对发布的text-v1语言/领域单元，使用规范ID映射到中文任务 | 只报告中文零售单元 |
| 本地Python3.14不满足上游要求 | 上游要求>=3.12,<3.14；远程使用Python3.12与独立环境 | 本地标准库测试不等于上游完整运行 |
| 新模型强度可能被旧LiteLLM静默过滤 | 上游设置drop_params=True；使用extra_body直接透传请求字段并做工具往返探测 | HTTP成功仍需服务端证据证明实际执行强度 |
| 当前只有Codex登录，没有独立API凭据 | 使用显式Codex桥接配置；保留原生Agent、工具和评分规则 | 传输及模型配置与官方直连条件不同，必须单独标注 |
| NL断言裁判模型在代码常量中固定 | 用受控启动钩子在父/子进程启动时替换配置及裁判模块中模型常量，语义通信裁判通过CLI传参 | 只改变裁判模型条件，不修改评分规则或答案 |
| 未识别模型价格被上游记为零 | 本项目报告实际费用为null，保留观察到的token和账单待核验说明 | 不把未知费用当免费 |
| 只统计成功返回轨迹会高估成绩 | 以运行清单题数×试次数固定分母，缺失和异常仍计入 | 未完成实验不能参与最终档位选择 |
| 相同用户/订单多道任务可能跨组 | 用实体与模板关联传递分组，冻结25/13/12清单 | 还需人工核查语义近似模板，不宣称独立泛化 |

## 2026-11-04：实测与报告一致性

| 现象 | 原因与处理 | 可解释的边界 |
|---|---|---|
| 52题三档原生评分均为0 | 核对原英文和中文库，题意要求保留24MP，但金标换30MP；原样保存评分并单列审计 | 不删除问题题分母，也不把该失败直接归因于模型 |
| low一段调用出现接近180秒长尾 | 与大文件传输窗口重合；暂停后长尾消失，将low时延标为不可比 | 没有证据排除后端排队等其他因素，不宣称唯一网络因果 |
| 更高强度未必得到更高单次成功率 | 完整同题开发矩阵分别保存真实model/effort与用户模拟轨迹 | 单次试验含随机波动，只称本次开发集观察，不称统计显著最优 |
| 相同成功数不能证明轨迹未变 | 汇总绑定清单、结果、分离轨迹及执行耗时文件的原字节SHA；正式复用核对选优报告 | 选档后不能静默换成另一批同分结果 |
| 只复用成功的开发题会污染全50题基线 | 校验全部开发题/试次/种子，失败也复制；原生按task_id/trial/seed跳过，逐轨迹摘要证明没有改写 | 13题历史耗时与新增37题实际耗时分开记录再相加 |
| 并列候选缺失耗时可能被过滤掉 | 缺失、非有限或非正时长均拒绝用耗时破平局 | 不修改预设规则迁就一次结果 |
| 并发运行后无法获得精确子组墙钟 | 从50条轨迹离线汇总25/13/12分数，子组wall_seconds留null | 不把轨迹时长之和冒充墙钟，也不虚构分组成本 |
| Windows受限临时目录使文件测试报权限错 | 将测试临时目录明确放在项目内，测试结束清理自己的临时目录 | 这是离线测试环境问题，不是模型调用或业务失败 |

实际完成状态与成绩统一以`../reports/实验进展与口径.md`及对应JSON为准；账单成本仍未知。新增工程模块和GEPA不属于当前已完成能力。
