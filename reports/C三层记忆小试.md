# C 配置三层记忆小试

本批选取 109 题历史无记忆实验中的困难案例。ECom 32 的历史 C 结果是失败，ECom 40 是通过。两题各在同一模型、工具、顾客设置和评分快照下重新运行一次关闭记忆、一次开启目录。题号从 0 起算。历史运行用于选题，效果由本批配对计算。

**2026-11-28 实测结果。** 关记忆办成 1/2，按需查 Wiki 办成 0/2。两个开启位置共发出 29 次客服模型请求，29 次带目录，主动打开正文和收到正文均为 0 次。本批没有观察到纠错，也没有两组都办对、可用于衡量节省轮数或 token 的题对。

## 核验口径

- 按位置核对模型输入中的目录及正文标记、读页工具事件、首次送达后的动作和模型回包用量。后续请求可能再次携带同一次打开的正文，因此打开次数和带正文的请求数分列。
- ECom 使用冻结版本的原评分器，保留总分和动作、检索、答复分项。轮数沿用上游口径，包含顾客结束轮。另计客服追问和同工具同参数的重复只读查询，执行前核对相同版本的顾客授权。
- 建库、有效短回放、有效整题以及修复前的诊断开销分列。输入包含缓存命中，合计为输入加输出。只有同题两组都通过且授权核对通过时，计算“保持通过时的节省率”。
- 首次联调发现读页返回被后续业务工具分支覆盖，产生了“记了读取事件，但下一笔没收到正文”的情况。修正后新增入口回归，核对实际发给模型的消息，再从冻结前缀重跑。修复前的回放只进入费用台账。
